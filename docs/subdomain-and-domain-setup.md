# Домен catlg.ru и поддомены [client].catlg.ru

Инструкция по привязке домена SpaceWeb к Vercel и реализации адресов вида `[client].catlg.ru`. Код пишется в Cursor по шагам ниже.

---

## Часть 1. Привязка домена к Vercel (DNS)

### 1.1. Добавить домены в Vercel

1. Зайти на [vercel.com](https://vercel.com) → выбрать проект.
2. **Settings** → вкладка **Domains**.
3. Добавить домены (по одному, кнопка Add):
   - **catlg.ru** — корень;
   - **www.catlg.ru** — с www (если нужен);
   - **\*.catlg.ru** — все поддомены (client.catlg.ru, shop.catlg.ru и т.д.).
4. Для каждого домена Vercel покажет нужные DNS-записи. Оставить вкладку открытой для следующего шага.

### 1.2. Настроить DNS в панели SpaceWeb

1. Войти в [cp.sweb.ru](https://cp.sweb.ru).
2. Меню: **Хостинг** → **Домены** → **Мои домены**.
3. Найти домен **catlg.ru** → нажать **DNS** (или «Управление зоной»).
4. Добавить записи по подсказкам Vercel.

**Ориентир (значения уточнять в Vercel):**

| Цель | Тип | Имя/поддомен | Значение |
|------|-----|----------------|----------|
| catlg.ru (корень) | A | @ или пусто | 76.76.21.21 |
| www.catlg.ru | CNAME | www | cname.vercel-dns.com |
| *.catlg.ru | CNAME | * | cname.vercel-dns.com |

- Имя/поддомен для wildcard в разных панелях: `*` или «поддомен: *».
- Сохранить изменения в зоне.

### 1.3. Проверка

- В Vercel → **Settings** → **Domains** дождаться статуса **Valid Configuration** для каждого домена.
- Обновление DNS обычно 5–30 минут, иногда до 24–48 часов.
- SSL (HTTPS) Vercel выдаёт сам после валидации.

## Часть 2. Реализация [client].catlg.ru в коде

Сейчас каталог открывается по пути **/[slug]** (например, catlg.ru/acme). Нужно, чтобы тот же каталог открывался по **acme.catlg.ru**. Slug должен браться из поддомена (часть перед `.catlg.ru`).

### 2.1. Где извлекать поддомен

**Вариант A — Middleware (рекомендуется)**  
Один раз на каждый запрос: в `middleware.ts` (в корне проекта) читать заголовок `Host`, парсить поддомен и передавать его в приложение (например, через заголовок `x-slug` или через редирект на путь `/[slug]`).

**Вариант B — Layout или страница каталога**  
Читать `headers().get('host')` в корневом layout или в странице, которая рендерит каталог, и извлекать поддомен там.

Выбрать один вариант и придерживаться его.

### 2.2. Логика парсинга хоста

Чётко описать (для себя или для Cursor):

1. **Откуда брать host**  
   В middleware: `request.headers.get('host')` или `request.nextUrl.hostname`. В Server Component: `headers().get('host')`.

2. **Как получить slug из host**  
   - Пример: host = `acme.catlg.ru` → slug = `acme` (часть до первой точки).
   - Уточнить домен продакшена: например, `catlg.ru`. Тогда: если host заканчивается на `.catlg.ru` и не равен `catlg.ru` и не равен `www.catlg.ru`, то поддомен = часть до `.catlg.ru`.

3. **Краевые случаи**  
   - **catlg.ru** (без поддомена) — slug нет; показывать главную/список клиентов/лендинг.
   - **www.catlg.ru** — не считать www клиентом; обрабатывать как корень.
   - **localhost / 127.0.0.1** — при разработке можно считать slug отсутствующим или задать тестовый поддомен (например, через `Host: acme.localhost` и парсить `acme`).

### 2.3. Передача slug в страницу каталога

**Вариант 1 — Редирект**  
В middleware: при запросе на `acme.catlg.ru` делать редирект на `https://catlg.ru/acme` (или на тот же host с путём `/acme`). Текущая логика `app/[slug]/page.tsx` не меняется; slug приходит из пути.

**Вариант 2 — Без редиректа (поддомен остаётся в адресной строке)**  
В middleware: установить заголовок (например, `x-slug: acme`) и в `app/[slug]/page.tsx` (или в общем layout) читать slug из этого заголовка, если он есть; иначе — из `params.slug`. Либо сделать одну страницу каталога, которая принимает slug из заголовка при запросе на поддомен и из params при запросе на catlg.ru/[slug].

Решить, какой вариант использовать, и описать в этом файле.

### 2.4. Поведение по типам URL

Закрепить в плане (без кода):

| Запрос | Ожидаемое поведение |
|--------|----------------------|
| **acme.catlg.ru** (любой путь) | Показать каталог бизнеса с slug = acme. Метаданные (title, description, favicon) — для этого slug. |
| **catlg.ru** | Главная / список клиентов / лендинг (на выбор). |
| **catlg.ru/acme** | Оставить работающим: каталог acme (как сейчас). |
| **unknown.catlg.ru** (slug нет в БД) | 404 или редирект на catlg.ru. |

Проверка «есть ли бизнес с таким slug» — запрос в БД (Supabase) по slug.

### 2.5. Регистрация клиента и выдача ссылки

- При создании/регистрации клиента (бизнеса) в БД сохранять уникальный **slug** (поле уже есть, например `business.slug`).
- При создании проверять уникальность slug.
- Адрес клиента считать: **https://{slug}.catlg.ru**.
- В админке и в уведомлениях клиенту показывать именно эту ссылку.

## Часть 3. Локальная разработка

- Локально поддомены можно тестировать так:
  - **Вариант 1:** в `hosts` прописать, например, `127.0.0.1 acme.catlg.ru` и открывать в браузере `http://acme.catlg.ru:3000` (порт по необходимости).
  - **Вариант 2:** использовать `acme.localhost:3000`, если логика парсинга хоста выделяет `acme` из `acme.localhost`.
- В коде парсинга хоста учесть домен продакшена (`catlg.ru`) и не падать на `localhost` / `127.0.0.1`; для localhost решить, откуда брать тестовый slug (поддомен или заголовок).

## Подсказки для Cursor

При реализации в Cursor можно давать такие задачи (по шагам):

1. «Добавь в middleware чтение Host и извлечение поддомена для домена catlg.ru; передай slug через заголовок x-slug.»
2. «В app/[slug]/page.tsx (или в layout) при запросе с поддоменом бери slug из заголовка x-slug, если он есть, иначе из params.slug.»
3. «Для запроса на корень (catlg.ru без поддомена) показывай [главную/лендинг].»
4. «Если поддомен есть, но бизнеса с таким slug в БД нет — верни 404 (или редирект на catlg.ru).»
5. «Учти в парсинге хоста localhost и www.catlg.ru.»

Файл конфигурации middleware: **middleware.ts** в корне проекта (если его ещё нет — создать). Домен продакшена вынести в константу (например, в `.env` или в конфиг), чтобы не хардкодить `catlg.ru` в нескольких местах.
