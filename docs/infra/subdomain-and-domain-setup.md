# Домен catlg.ru и поддомены [client].catlg.ru

Инструкция по привязке домена SpaceWeb к **VPS** и реализации адресов вида `[client].catlg.ru`. Деплой приложения на VPS описан в `docs/infra/vps-deploy-ubuntu.md`. Код парсинга поддоменов пишется в Cursor по шагам ниже.

---

## Часть 1. Привязка домена к VPS (DNS в SpaceWeb)

Домен остаётся у SpaceWeb; DNS-записи направляют трафик на IP вашего VPS. Wildcard поддомены настраиваются без смены nameservers (в отличие от Vercel).

### 1.1. Узнать IP VPS

IP сервера вы получили при покупке VPS. Он понадобится для всех A-записей ниже.

### 1.2. Настроить DNS в панели SpaceWeb

1. Войти в [cp.sweb.ru](https://cp.sweb.ru).
2. Меню: **Хостинг** → **Домены** → **Мои домены**.
3. Найти домен **catlg.ru** → нажать **DNS** (или «Управление зоной»).

**Если видите сообщение:** «Невозможно изменить записи DNS, поскольку домен делегирован на сторонние DNS-серверы» — это ограничивает только **редактирование и удаление** уже существующих записей (MX, autoconfig и т.п.). **Добавлять новые записи** (A для корня, www и wildcard) при этом можно — этого достаточно для привязки домена к VPS.

4. Добавить записи так, чтобы трафик шёл на VPS (при необходимости — только новые, не трогая существующие):

**Готовые записи для добавления в SpaceWeb** (поля формы: Поддомен, Тип, Значения; суффикс `.catlg.ru` подставляется автоматически):

| Цель | Поддомен | Тип | Значения |
|------|----------|-----|----------|
| catlg.ru (корень) | *оставить пустым* | A | 77.222.32.54 |
| www.catlg.ru | www | A | 77.222.32.54 |
| все поддомены (*.catlg.ru) | * | A | 77.222.32.54 |

- В поле «Поддомен» вводить только имя; для корня — оставить пустым (как в подсказке в панели).
- Записи для почты (MX, TXT, autoconfig, autodiscover) **не удалять**.
- После каждой записи нажать «Сохранить».

### 1.3. Проверка

- Обновление DNS обычно 5–30 минут, иногда до 24–48 часов.
- С вашей машины: `nslookup catlg.ru`, `nslookup test.catlg.ru` — должны резолвиться в `<IP_VPS>`.
- SSL (HTTPS) настраивается на VPS через Certbot — см. `docs/infra/vps-deploy-ubuntu.md`, раздел 12.

## Часть 2. Реализация [client].catlg.ru в коде

Цель: каталог каждого клиента открывается **только** на поддомене вида **`{slug}.catlg.ru`** (например, `crusty.catlg.ru`).  
Доступ по пути `catlg.ru/{slug}` должен быть **закрыт (404)**, чтобы не было дублей.

### 2.1. Где извлекать поддомен

**Вариант A — Middleware (рекомендуется)**  
Один раз на каждый запрос: в `middleware.ts` (в корне проекта) читать заголовок `Host`, парсить поддомен и делать **rewrite** на внутренний путь `/{slug}{pathname}`. Это **не redirect** — адрес в браузере остаётся `{slug}.catlg.ru`.

Примечание: в `app/[slug]/layout.tsx` (или `page.tsx`) делаем guard по Host, чтобы `catlg.ru/{slug}/*` всегда возвращал 404.

### 2.2. Логика парсинга хоста

Чётко описать (для себя или для Cursor):

1. **Откуда брать host**  
   В middleware: `request.headers.get('host')` или `request.nextUrl.hostname`. В Server Component: `headers().get('host')`.

2. **Как получить slug из host**  
   - Пример: host = `crusty.catlg.ru` → slug = `crusty` (часть до первой точки).
   - Уточнить домен продакшена: например, `catlg.ru`. Тогда: если host заканчивается на `.catlg.ru` и не равен `catlg.ru` и не равен `www.catlg.ru`, то поддомен = часть до `.catlg.ru`.

3. **Краевые случаи**  
   - **catlg.ru** (без поддомена) — slug нет; показывать главную/список клиентов/лендинг.
   - **www.catlg.ru** — не считать www клиентом; обрабатывать как корень.
   - **localhost / 127.0.0.1** — в dev тестируем поддомены через `hosts` (см. Часть 3). Поддержку `acme.localhost` не используем.

### 2.3. Передача slug в страницу каталога

Используем один вариант:
- **Без редиректа (поддомен остаётся в адресной строке)**  
  В middleware делаем **rewrite**: `crusty.catlg.ru/...` → внутренняя обработка `/{slug}/...`, поэтому slug приходит обычным способом через `params.slug`.

### 2.4. Поведение по типам URL

Закрепить в плане (без кода):

| Запрос | Ожидаемое поведение |
|--------|----------------------|
| **crusty.catlg.ru** (любой путь) | Показать каталог бизнеса с slug = crusty. Метаданные (title, description, favicon) — для этого slug. |
| **catlg.ru** | Главная / список клиентов / лендинг (на выбор). |
| **catlg.ru/crusty** | **404** (анти-дубли; каталог доступен только на поддомене). |
| **unknown.catlg.ru** (slug нет в БД) | **404**. |

Проверка «есть ли бизнес с таким slug» — запрос в БД (Supabase) по slug.

### 2.5. Регистрация клиента и выдача ссылки

- При создании/регистрации клиента (бизнеса) в БД сохранять уникальный **slug** (поле уже есть, например `business.slug`).
- При создании проверять уникальность slug.
- Адрес клиента считать: **https://{slug}.catlg.ru**.
- В админке и в уведомлениях клиенту показывать именно эту ссылку.

## Часть 3. Локальная разработка

- Локально поддомены можно тестировать так:
  - В `hosts` прописать:
    - `127.0.0.1 catlg.ru`
    - `127.0.0.1 crusty.catlg.ru`
  - Открывать в браузере:
    - `http://catlg.ru:3000` (главная)
    - `http://crusty.catlg.ru:3000` (каталог)
    - `http://catlg.ru:3000/crusty` должно быть **404**
  - Важно: если логиниться на `localhost`, cookies не будут доступны на `*.catlg.ru`. Для dev логин используйте `http://catlg.ru:3000/login` или `http://crusty.catlg.ru:3000/login`.

## Часть 4. Чек-лист

- [ ] DNS в SpaceWeb: A @ → IP VPS; A www → IP VPS; A * → IP VPS (wildcard). См. также `docs/infra/vps-deploy-ubuntu.md`, раздел 11.
- [ ] На VPS: Nginx принимает catlg.ru, www.catlg.ru, \*.catlg.ru и проксирует с сохранением заголовка Host (см. infra/vps-deploy-ubuntu.md, раздел 10).
- [ ] Выбрано место извлечения поддомена (middleware).
- [ ] Реализован парсинг host → slug с учётом catlg.ru, www.
- [ ] Реализована передача slug в страницу каталога (rewrite без редиректа).
- [ ] Запрос на поддомен показывает каталог нужного slug; метаданные для этого slug.
- [ ] Запрос на корень (catlg.ru / www) обработан (главная/лендинг/список).
- [ ] Несуществующий поддомен → 404.
- [ ] `catlg.ru/{slug}` → 404 (анти-дубли).
- [ ] У клиентов в БД уникальный slug; адрес клиента = https://{slug}.catlg.ru.
- [ ] Локальная проверка поддоменов работает (hosts или localhost).

## Подсказки для Cursor

При реализации в Cursor можно давать такие задачи (по шагам):

1. «Добавь в middleware чтение Host и извлечение поддомена для домена catlg.ru; сделай rewrite на `/{slug}{pathname}`.»
2. «В app/[slug]/layout.tsx (или page.tsx) запрети `catlg.ru/{slug}/*` (404), оставив доступ только на `{slug}.catlg.ru`.»
3. «Для запроса на корень (catlg.ru без поддомена) показывай [главную/лендинг].»
4. «Если поддомен есть, но бизнеса с таким slug в БД нет — верни 404.»
5. «Не использовать `acme.localhost`, тестировать поддомены через hosts.»

Файл конфигурации middleware: **middleware.ts** в корне проекта (если его ещё нет — создать). Домен продакшена вынести в константу (например, в `.env` или в конфиг), чтобы не хардкодить `catlg.ru` в нескольких местах.
