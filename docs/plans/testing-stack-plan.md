# Minimal Testing Stack

Дата: 2026-03-08

## Выбранный стек

- `Vitest`
- `@testing-library/react`
- `@testing-library/jest-dom`
- `jsdom`

## Почему именно так

- проект на `Next.js + React + TypeScript`
- нужен минимальный стек без тяжёлого e2e-контура на первом шаге
- основная польза сейчас в быстрых проверках критической логики и ключевых UI-сценариев
- `Vitest` запускается быстрее и проще для локальной разработки, чем полноценный e2e-стек

## Что покрываем этим стеком

На следующем шаге этим стеком разумно покрывать:

1. публичный каталог
2. корзину
3. оформление заказа
4. доступ к админке
5. создание и редактирование товара

## Что пока не добавляем

- `Playwright`
- тяжёлые browser e2e
- сложный mock-инфраструктурный слой

Это можно добавить позже, если минимальный набор тестов покажет реальную пользу.

## Практическое правило

На этом этапе тесты должны быть:

- быстрыми
- локально запускаемыми
- сфокусированными на критическом потоке
- без избыточной инфраструктуры

- выбрать 5-10 тест-кейсов с максимальной пользой
