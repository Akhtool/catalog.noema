# План исправления багов промокодов

План рассчитан на пошаговое исправление с помощью Cursor AI. Выполняй этапы по порядку; каждый этап — отдельный запрос к ассистенту.

**Правила проекта:** заказы не сохраняются на сервере (см. `.cursor/rules/project-rules.mdc`). Серверная проверка промо (п. 3 ниже) в текущем контракте не требуется — в плане помечена как опциональная/на будущее.

## Этап 1. Привязка промо к бизнесу (кросс-бизнес и устаревший промо) ✅

**Статус:** Реализовано (проверено и дополнено). Типы, store (per-business), `applyPromo(businessId, promo)`, `getDiscountAmount(businessId)` с проверкой `businessId` и `minOrder`, валидация при открытии drawer уже были. Добавлено: санитизация при гидрации (очистка `appliedPromo` без `businessId` в хранимых слайсах) и явная проверка `appliedPromo.businessId === business.id` в UI перед показом блока промо.

**Проблема:** Корзина одна на всё приложение. Если пользователь применил промо на витрине A и перешёл на витрину B, скидка продолжает считаться по данным A. После гидрации из localStorage промо может быть от другого бизнеса или уже отключён админом.

**Что сделать:**

1. **Типы** (`types/index.ts`):
   - В `AppliedPromo` добавить поле `businessId: string` (UUID бизнеса, для которого применён промо).
   - При необходимости обновить `Cart` / использование в `store/cart.ts`.

2. **Store** (`store/cart.ts`):
   - В `applyPromo`: принимать `businessId: string` вторым аргументом (или из `Business`), при успешной валидации сохранять в `appliedPromo.businessId`.
   - В `getDiscountAmount`: если в state есть `appliedPromo`, но нет `businessId` в текущем контексте — не считать скидку (или считать 0). Для этого в store нужно либо передавать текущий `businessId` в getDiscountAmount, либо хранить `businessId` в appliedPromo и сравнивать при отображении (см. п. 3).
   - В `partialize` и при гидрации сохранять/восстанавливать `appliedPromo` с `businessId`.

3. **UI** (`components/cart/cart-drawer.tsx`):
   - При вызове `applyPromo(business.promo)` передавать `business.id` (или вызывать `applyPromo(business.promo, business.id)` после изменения сигнатуры).
   - При отображении «Промокод X применён» и блоков «Подытог / Скидка / Итого»: если `appliedPromo.businessId !== business?.id`, не показывать скидку и считать промо недействительным (можно сбросить appliedPromo при открытии drawer при несовпадении).

4. **Валидация после гидрации:**
   - При первом отображении корзины после загрузки страницы (например, при открытии drawer в `cart-drawer.tsx`) проверять: если есть `appliedPromo`, то вызвать `validatePromo(business.promo, appliedPromo.code, getSubtotal())` для текущего `business`. Если не valid — очистить `appliedPromo` и `promoError` в store. Учесть, что промо привязан к бизнесу: проверять только если `appliedPromo.businessId === business.id`.

**Подсказка для Cursor:**  
«Реализуй привязку применённого промокода к бизнесу: добавь businessId в AppliedPromo, сохраняй его при applyPromo и при отображении в корзине показывай скидку только если appliedPromo.businessId совпадает с текущим business.id. При открытии корзины перепроверяй appliedPromo через validatePromo для текущего бизнеса и при невалидности сбрасывай промо.»

## Этап 2. Повторная валидация при изменении суммы (minOrder) ✅

**Статус:** Уже реализовано. В `getDiscountAmount` проверяется `subtotal < (appliedPromo.minOrder ?? 0)` → возврат 0. В UI при скидке 0 из-за minOrder показывается подсказка «Минимальная сумма заказа для промокода: X ₽» (промо не сбрасывается при уменьшении корзины).

**Проблема:** Промо применён при подытоге 900₽ (minOrder 800₽). После уменьшения количества подытог 500₽, но скидка по-прежнему показывается.

**Что сделать:**

1. **Store** (`store/cart.ts`):
   - В `getDiscountAmount`: перед вызовом `calculatePromoDiscount` проверять `appliedPromo.minOrder`. Если `getSubtotal() < (appliedPromo.minOrder ?? 0)`, возвращать 0 (и опционально не считать appliedPromo действительным для отображения).
   - Либо ввести хелпер «активен ли промо для текущей корзины»: проверка minOrder + при необходимости дат; если не активен — возвращать скидку 0. В UI можно при этом продолжать показывать «Промокод X применён», но с подсказкой «минимальная сумма не достигнута» и скидка 0 — или сбрасывать appliedPromo при subtotal < minOrder (жёсткий вариант).

2. **Рекомендация:** Не сбрасывать промо автоматически при падении суммы, а показывать скидку 0 и при желании текст «Минимальная сумма заказа для промокода: X ₽». Тогда при увеличении суммы скидка снова начнёт применяться без повторного ввода кода.

**Подсказка для Cursor:**  
«В getDiscountAmount учитывай minOrder из appliedPromo: если getSubtotal() меньше appliedPromo.minOrder, возвращай скидку 0. Опционально в UI покажи подсказку о минимальной сумме, когда промо применён, но скидка 0 из-за minOrder.»

## Этап 3. Серверная проверка промо (опционально / вне текущего контракта)

**Проблема:** Скидка считается только на клиенте; при появлении сохранения заказов на сервере возможна подделка суммы скидки.

**Что сделать в будущем:**  
При появлении в product-contract и data-model сохранения заказов на бэкенде — при создании заказа проверять промокод на сервере и пересчитывать discountAmount (или отклонять заказ при несовпадении). Сейчас по правилам проекта заказы не сохраняются на сервере, поэтому этот этап не реализовывать без обновления контракта.

**Подсказка для Cursor:**  
Пока не использовать. При изменении контракта: «Добавь серверную проверку промокода при создании заказа: валидация кода и расчёт скидки на бэкенде.»

## Этап 5. Итоговая проверка и тесты

После этапов 1 и 2:

1. Проверить сценарий: витрина A → применить промо → переход на витрину B → корзина не должна показывать скидку от A (или промо сброшено).
2. Проверить: применить промо при сумме выше minOrder, уменьшить корзину ниже minOrder — скидка 0, при увеличении снова — скидка появляется.
3. Проверить: применить промо, перезагрузить страницу (гидрация) — при невалидном или отключённом промо appliedPromo сбрасывается; при валидном — скидка отображается.
4. Убедиться, что в сообщении заказа (lib/order.ts) по-прежнему выводятся подытог, скидка и итог и что при скидке 0 из-за minOrder итог совпадает с подытогом.
