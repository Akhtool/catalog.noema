# План: онбординг и вход для бизнеса

## Для команды: как открыть страницу онбординга

Страница онбординга открывается только как внутренний инструмент команды.

Открывать так:
- локально: `http://catlg.ru:3000/onboarding?key=ВАШ_КЛЮЧ`
- прод: `https://catlg.ru/onboarding?key=ВАШ_КЛЮЧ`

Если ключ не передан или не совпадает с `ONBOARDING_ACCESS_KEY`, будет редирект на `/`.

---

## 1. Модель работы

- Бизнес не регистрируется сам.
- Команда платформы создаёт бизнес, поддомен и учётную запись владельца.
- После этого команда передаёт владельцу:
  - ссылку на каталог: `https://[slug].catlg.ru/`
  - ссылку на вход: `https://[slug].catlg.ru/login`
  - логин и пароль
- После входа владелец остаётся на `https://[slug].catlg.ru/`, а интерфейс страницы переключается в режим управления каталогом.

См. также: `docs/reference/routing-rules.md`.

---

## 2. Сценарии

### 2.1 Команда регистрирует новый бизнес

1. Команда открывает `catlg.ru/onboarding?key=...`.
2. Если нет активной сессии, регистрирует или использует внутреннюю учётную запись для шага онбординга.
3. Создаёт бизнес: название, slug и владелец.
4. После создания можно сразу проверить витрину бизнеса на `{slug}.catlg.ru`.
5. Команда отправляет владельцу ссылку на каталог, ссылку на вход и учётные данные.

### 2.2 Владелец бизнеса входит в каталог

1. Владелец получает от команды `https://[slug].catlg.ru/login` и учётные данные.
2. Открывает именно этот URL.
3. Вводит email и пароль.
4. После входа попадает на `https://[slug].catlg.ru/`.
5. На той же странице появляется owner/admin overlay для управления каталогом.

---

## 3. Маршруты

| Маршрут | Кто использует | Поведение |
|--------|-----------------|-----------|
| `catlg.ru/` | Все | Публичный лендинг платформы. |
| `{slug}.catlg.ru/` | Клиенты, владелец | Публичный каталог бизнеса; после входа владельца эта же страница показывает admin overlay. |
| `{slug}.catlg.ru/login` | Владелец бизнеса | Единственная штатная точка входа владельца. |
| `catlg.ru/onboarding?key=...` | Только команда | Внутренний онбординг для создания бизнеса и владельца. |
| `catlg.ru/signup` | Никто снаружи | Публичная self-service регистрация отключена; редирект на `/`. |
| `catlg.ru/admin` | Только команда, позже | Зарезервировано под будущую платформенную админку. |
| `catlg.ru/admin/sign-in` | Только команда, позже | Зарезервировано под будущий вход в платформенную админку. |

---

## 4. Текущее поведение кода

- `catlg.ru/login` не используется как штатный вход владельца и редиректит на `/`.
- `catlg.ru/signup` редиректит на `/`.
- `catlg.ru/onboarding` без валидного `key` редиректит на `/`.
- Владелец бизнеса должен заходить только через поддомен своего бизнеса.
- После входа редирект ведёт на корень поддомена бизнеса, а не на отдельный tenant-admin URL.

---

## 5. Что уже реализовано

- Убран публичный self-service signup для бизнеса.
- Онбординг переведён в режим "только для команды".
- Добавлена защита `ONBOARDING_ACCESS_KEY`.
- Root-domain `/login` не используется как owner entry.
- Owner workflow зафиксирован на `{slug}.catlg.ru/login` -> `{slug}.catlg.ru/`.
- Root-domain `catlg.ru/admin` зарезервирован под будущую платформенную админку.

## 7. Статус

Текущий маршрутный контракт зафиксирован и соответствует коду: владелец бизнеса использует только свой поддомен, а root-domain маршруты онбординга и будущей админки относятся к внутренним процессам команды.
