# План реализации: выбор акцентного цвета (на уровне Business)

Дата: 2026-02-08  
Контекст: Next.js (App Router) + Tailwind + shadcn/ui + Zustand + Supabase  

## Цель

Дать бизнесу (owner/admin) возможность выбрать **акцентный цвет** для своего публичного каталога, чтобы оформление (кнопки/бордеры/бейджи/акценты) соответствовало бренду.

## Важные ограничения (из источников истины проекта)

- Любые изменения фич/модели данных сначала отражаем в:
  - `docs/reference/product-contract.md`
  - `docs/reference/data-model.md`
- Никаких “на будущее” абстракций и усложнений. Делаем минимально необходимое.

## Предположения (явные)

- Акцентный цвет настраивается **для публичного каталога конкретного бизнеса** (страницы `app/[slug]/**`), а не “глобально для админки/логина”.
- Настройка хранится в таблице `business` (это логично: “визуальное оформление” уже описано в `reference/data-model.md` как часть Business).
- Первый релиз делаем безопасно: **пресеты + возможность ручного выбора**, с автоматическим расчётом контрастного текста (минимум белый/чёрный).

## Варианты реализации (выбрать один как базовый)

### Вариант A (рекомендую: минимальные изменения кода)

Сделать существующий `brand-yellow` **динамическим через CSS variable**, чтобы текущие классы (`bg-brand-yellow`, `text-brand-yellow`, `border-brand-yellow`, `shadow-yellow-glow`, `.../20`) продолжили работать без массового рефакторинга.

- Tailwind: `colors["brand-yellow"] = "hsl(var(--brand-yellow) / <alpha-value>)"`
- На странице бизнеса выставлять `--brand-yellow` (и при желании синхронизировать `--primary` для shadcn).

Плюсы: почти нулевой объём правок по компонентам.  
Минусы: “brand-yellow” как имя токена остаётся исторически неидеальным.

### Вариант B (семантически чисто, но дороже)

Мигрировать UI с `brand-yellow` на `primary` (`bg-primary`, `text-primary`, `ring-primary`), а акцент задавать через `--primary`.

Плюсы: красивый дизайн-токен подход.  
Минусы: много замен по компонентам и выше риск “не докрасить” куски.

### Вариант C (премиум)

Хранить небольшую палитру: `primary`, `primary-foreground`, `ring`, `accent` и т.п., и применять всё как тему.

Плюсы: консистентный дизайн.  
Минусы: больше UI/валидации, больше риск регресса.

**База для поэтапной реализации:** Вариант A → затем (по желанию) постепенный переход к B.

## Этап 1. Схема БД (Supabase)

### 1.1 Миграция

- [ ] Добавить SQL в `migrations/` в стиле существующих файлов:
  - имя: `migrations/add_business_theme_brand.sql`
  - `ALTER TABLE business ADD COLUMN IF NOT EXISTS theme_brand_hsl TEXT;`
  - `ALTER TABLE business ADD COLUMN IF NOT EXISTS theme_brand_foreground TEXT;` (если нужен)

Формат:
- `theme_brand_hsl`: строка вида `"48 100% 50%"` (без `hsl(...)`, только значения)

Критерий готовности:
- [ ] Миграция применена в Supabase, новые колонки видны.

План отката:

## Этап 3. Применение темы на публичной странице каталога (SSR без мигания)

Цель: задать CSS variables **сразу на сервере** (в `app/[slug]/page.tsx`), чтобы не было FOUC.

### 3.1 CSS variables, которые будем выставлять

Минимальный набор:
- `--brand-yellow` (для текущих `bg-brand-yellow/...`)
- (желательно) `--primary` и `--primary-foreground` (чтобы shadcn компоненты тоже совпали по акценту)

### 3.2 Где выставлять

- [ ] В `app/[slug]/page.tsx` обернуть всё содержимое в `<div style={...}>...</div>`
  - если у бизнеса `themeBrandHsl === null` → не выставлять (останется дефолт из `globals.css`)
  - если есть → выставить

Типизация:
- в React style нужно прокинуть CSS custom properties (обычно через `as React.CSSProperties` + индексный ключ).

Критерий готовности:
- [ ] Открываем `{slug}` каталог — акцент меняется сразу, без client-only эффекта.

## Этап 4. Tailwind токены: сделать `brand-yellow` динамическим

Цель: не переписывать кучу компонентов, а “подложить переменную” под существующий токен.

### 4.1 `tailwind.config.ts`

- [ ] Заменить `colors["brand-yellow"]` с hex `#ffd600` на:
  - `"hsl(var(--brand-yellow) / <alpha-value>)"`
- [ ] (опционально) переименовать `boxShadow["yellow-glow"]` в нейтральный и/или завязать на `--brand-yellow`, например:
  - `hsl(var(--brand-yellow) / 0.4)`

### 4.2 `app/globals.css`

- [ ] В `:root` задать дефолт:
  - `--brand-yellow: 48 100% 50%;` (пример, подобрать под текущий `#ffd600`)
- [ ] (если используете `.dark`) решить:
  - либо такой же бренд в dark,
  - либо другой дефолт (в V1 можно оставить тот же).

Критерий готовности:
- [ ] `bg-brand-yellow/20`, `border-brand-yellow/30` и т.п. продолжают работать.
