# План безопасной миграции зависимостей (02.02.2026)

Цель: обновить выбранные библиотеки так, чтобы минимизировать риск поломок, быстро находить причину регресса и откатываться точечно.

## Базовый безопасный алгоритм (для каждой библиотеки)

- Делай отдельную ветку/PR под каждое обновление (или логичную связку).
- Обновляй **по одной библиотеке за раз** (или связку, если версии должны совпадать).
- После каждого шага прогоняй проверки (Windows):

```bash
npm ci
npm run lint
npm run build
npm run start
```

- Ручная регрессия после каждого апдейта:
  - логин/сессия
  - админка (создание/редактирование сущностей)
  - каталог, корзина/checkout
  - загрузка/обрезка изображений (если используется)

## 1) Next.js (минор в ветке 15): `next` + `eslint-config-next`

Цель: обновиться в пределах 15-й ветки (низкий риск), синхронизируя `next` и `eslint-config-next`.

### Шаги

- Прочитать release notes/upgrade guide для диапазона 15.2 → 15.5 (особенно App Router, route handlers, Turbopack, кэши).
- Обновить **пакеты парой**:

```bash
npm i next@^15.5.11 eslint-config-next@^15.5.11
```

- Проверить критичные места:
  - `app/**/route.ts` (runtime, cookies/headers, edge/node особенности)
  - предупреждения/ошибки сборки в `next build` (часть проблем видна только в prod)
- Прогнать ручную регрессию в `npm run dev` и отдельно в `npm run build && npm run start`.
